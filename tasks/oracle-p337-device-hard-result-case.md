# Oracle Case: P337 Device Surface Hard-Result Contract

Project: WorldForge, TypeScript/Node backend with a gameplay cycle runtime. The core loop is meant to feel like an interactive novel/game: GM/Judge/Stage 4 decide what happened, Stage 6/Narrator renders the settled result into playable prose. Stage 6 must not invent hard facts, but it may add low-stakes visible/sensory texture around accepted hard facts.

User constraints:
- No regex/prose banlist patches.
- No gameplay fallback, no repair loop, no backwards-compat shims.
- No deterministic projection as a narrator replacement for normal turns.
- Hard facts stay strict: movement, item custody, route, time, injury/condition, dialogue quote, secret/world fact, resource, relationship, important object/affordance.
- Soft prose stays free: harmless visible/sensory adjectives and atmosphere do not become world-state authority.
- If player later grabs onto a soft detail, the next turn adjudicates it normally.

Current P337 fix already did:
- Stage 6 prompt now gives a soft prose budget and forbids backend receipt dumps.
- Opening no longer prints route/backend summaries.
- GM Read routes sensory follow-ups into local observation, not scene-beat echo.
- Device no-surface summaries no longer enumerate unavailable facets in the player-facing beat.

Current failure:
- Fresh live playtest campaign `p337-opening-live-shibuya-20260626-0845` starts and moves successfully.
- Turn action:
  `I check the burner phone screen for signal, battery, missed calls, messages, notifications, or anything already open, without pressing anything else.`
- Stage 4/settlement correctly produce a bounded hard result like:
  `Burner phone's visible surface shows no readable public result for the requested surface check.`
- Runtime then asks Stage 6 to narrate it.
- Validator currently requires exact copy for backend fact role `device_surface_beat`, because previous live output expanded into unsafe hard claims such as screen state, signal bars, battery icon, calls/messages/notifications.
- Fresh live turn now fails with `CleanNarrationValidationError: sentence_plan_not_supported ... must copy exact sentence-plan material e6.f1`; pre-turn state is restored and player sees a failed turn.

Question:
What is the cleanest minimal runtime contract that keeps the game playable and safe?

I need advice on choosing between:
1. Treat `device_surface_unavailable` as an exact typed hard-result renderable sentence, generated by runtime as the settled result, with Stage 6 only allowed to add separate accepted scene texture if present. This avoids asking the model to exact-copy a receipt. Concern: user explicitly banned deterministic projection as narrator replacement for normal turns, so this must be framed as exact hard-result rendering, not fallback.
2. Relax exact-copy and allow bounded paraphrase for `device_surface_beat` as long as only the beat/device/scene refs are cited. Concern: without adding a regex/prose banlist, this may let in hidden/mechanical affordance claims again.
3. Change prompt/schema/sentencePlan so Stage 6 produces a structured exact hard-result sentence object for `device_surface_unavailable` and model-authored prose only for soft surrounding texture. Concern: native JSON cannot truly force exact text and the model already ignores exact-copy.

Desired answer:
- Recommend one approach with reasoning.
- Explain how it preserves the WorldForge division of labor: adjudication in GM/Judge/Stage4, presentation in Narrator, world-state authority only for accepted hard facts.
- Give a small implementation plan and focused tests.
- Call out anything that risks recreating the original Stage 6 truth-contract problem.
